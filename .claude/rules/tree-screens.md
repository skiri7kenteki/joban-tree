# ツリーの画面（入力・生成中・閲覧・一覧・設定・書き出し）

> CLAUDE.md から移した仕様（2026-11-24）。この機能の仕様を変えたら、このファイルを直す。
> 下のパスのファイルを読んだときだけ読み込まれる。

## 画面の仕様（段階1以降）
- 入力画面：棋譜の貼り付け（KIF/KI2/CSA/SFEN/USI の指し手列。段階4-2〜 欄はふだん閉じ、読み込んだら閉じる。作るボタンは画面の下に固定）、平手から盤をタップして進める、手順を前後して開始局面を選ぶ、「自分は先手／後手」（初期値はその局面の手番の反対側）
  - 段階5-1（v0.11.0〜）「戦型から選ぶ」：グループ → 戦型 → 選ぶと、その手順を読み込んだ状態（貼り付けの後と同じ）。
    **自分の側は戦型の `mySide` のまま固定**（手順を前後しても変えない。切り替えはできる。持ち主の判断 2026-11-16。棋譜の読み込み・初期局面に戻すで戦型は外れ、これまで通りに戻る）。
    戦型の出発点かその先の局面なら、名前とメモを手順の操作の下（iPad 横は右の列）に出し、ツリーの名前を戦型の名前にする（その先なら「戦型名 → △8四飛まで」）。
    戦型の途中まで戻したり、手順から外れたりしたら、メモは隠し、名前はこれまで通り。`reviewed: false` の戦型には「未確認」の印
- 生成中：経過時間・調べた局面数・深さ・停止ボタン。生成中もできた枝からたどれる
- 閲覧画面（中心）：上に盤面、下に「この局面の候補手リスト」（相手の手番＝相手の応手を評価値・ラベル付きで全部、自分の手番＝自分の対応を検証済み／未検証の印付きで）。
  候補手タップで 1 手進む。「‹」と左右スワイプで 1 手戻る・進む。手順のパンくずリスト（「‹」と同じ行）。「ここから展開」「この手を検証」「KIF をコピー」
  - 段階4-1（v0.7.0）：相手の応手の行に「→ 自分の対応」（子の自分ノードの先頭の手）と、枝の先の様子（`src/tree/browse.ts`、数え方は PROGRESS.md）を併記。
    評価値は自分の対応の後の値。**盤上に候補手の矢印は描かない**（v0.7.0 で入れたが、持ち主の判断 2026-11-14 で v0.7.1 にやめた）。スマホ縦 390×844 で候補手 3 行が見えること（`e2e/phase4.spec.ts`）。
    **v0.12.2〜 幅 360 以上・高さ 640 以上なら候補手 3 行がスクロールなしで見える**（持ち主の Android が幅 360 相当）：スマホ縦（左右に並べない配置）では、
    盤の幅を「画面の幅」と「画面の高さから盤の上の部分・持ち駒の行・パンくず・候補手の見出し・3 行目までの実際の高さを引いた高さ」の小さい方にして、左右の真ん中に置く
    （`src/app/boardFit.ts` が描くたび・画面の大きさが変わるたびに測る。文字を大きくした端末ではその分だけ盤が縮む。盤の幅は 220px より小さくしない）。
    ヘッダーのボタンは折り返さず（見出しを … で縮める）、候補手の見出しは 1 行（「評価値：対応の後・☗先手から」、入りきらなければ … ）。
    **v0.12.3〜 候補手が 4 つ以上**（「ふつう」「じっくり」の初期設定は 4 つ）：盤を画面幅の 85%（`KEEP_RATIO`、仮の値）以上に保って 4 行目まで収まるなら収める。（段階14 でやめた：3 行目まで見え、4 行目からは枠の中でスクロール）
    収まらなければ 4 行目の上半分をのぞかせる（そのために 85% 未満には縮めない。3 行目までを収める分の縮小は別）。5 つ以上でも目標は 4 行まで。
    見出しに件数（「相手の応手（4）」。除外した手は数えない）。
    **v0.12.4〜 入力画面・復習画面も同じ仕組み**（`measureFitAbove`。盤を包む要素に `boardFitProps` で `.board-fit` と `--board-fit-w`）：（段階14 で measureFitFrame に置き換えた）
    入力画面は盤・先手の持ち駒の行・手順の操作（‹ ›）を、下に固定した作るボタンのバーの上に（貼り付け欄を開いている間はしない）。読み込んだ手数の一言は盤の上の案内の行と入れ替える。
    復習画面は盤と問題のカード（まちがえた後の「もう一度」「正解を見る」も）を画面の中に。同じ問題の間は、一度縮めた盤を戻さない（盤が行ったり来たりしない）。
    駒をタップできる盤の持ち駒の行は、駒が無くても駒があるときと同じ高さ（52px）にして、駒を取った瞬間に盤の大きさが変わらないようにした
- 保存と一覧：IndexedDB に自動保存。一覧には自分の側と開始局面までの最後の 3 手（`prefixSummary`、段階4-2）。
  **段階7-1（v0.15.0〜、持ち主の判断 2026-11-17）トップ画面の整理**（`src/tree/organize.ts`・`src/app/recent.ts`）：
  - グループ＝「戦型のグループ × 自分の側」（見出し「横歩取り（後手番）3」）。グループの順は固定（戦型の一覧の順＝同梱 → 自分で登録、同じグループは後手番 → 先手番）、「その他」はいちばん下。
    中は用意済みがいちばん上、あとは更新日の新しい順。開閉でき、閉じた key を localStorage `joban-tree.home-collapsed` に覚える（初めては全部開く）
  - どの戦型か（`templateOf`）：ツリーの `templateId`（形式 5〜。作るときに記録：選んだ戦型、無ければ手順がいちばん長く一致する戦型、用意済みのコピーは元の同梱テンプレート）があり、その戦型が今もあればそれ。
    無ければ開始局面までの手順から推定（平手の初期局面から始まり、戦型の手順で始まるもの。いちばん長い戦型）。**推定はツリーに書き込まない**（後から戦型を登録すれば古いツリーも移る）
  - 最近開いた：閲覧画面を開いたときに localStorage `joban-tree.recent`（最大 20 件）に記録。**ツリーのデータ・書き出しには入れない**。ツリーが 4 つ以上のとき、新しい順に 3 件（`recent-item`）
  - 絞り込みの欄は v0.29.0 でやめた（持ち主の依頼。使わなかったため）。速度測定へのリンクは設定の「エンジン」。名前の変更・削除（確認あり）。書き出し＝分岐付き KIF／現局面までの KIF／JSON。取り込み＝JSON（上書き時は確認）。
  共有は Web Share API（ファイルまたはテキスト）、使えなければクリップボード。iPad の共有メニューから「"ファイル"に保存」できること
- 設定：評価関数（11micro／11mini）、スレッド数（使える場合のみ）、ハッシュサイズ、W・N・ラベルのしきい値、プリセットの中身
- フッター：左にバージョン、右に「気づきを送る」（GitHub の Issue 作成画面を開く。ツリーのデータは送らない）
  - 「かんたん予定」と同じ：一行の入力 → タイトル【気づき】＋本文（画面名・バージョン・日付）。ホーム画面アプリでは `x-safari-https://` で Safari 本体に開く
- 設定は localStorage（`joban-tree.settings`、`src/app/settings.ts`）。読むときは `normalizeSettings` で範囲内に直す。エンジンの設定（評価関数・スレッド・ハッシュ）が変わったら、次に使うときにエンジンを作り直す
- 書き出し
  - KIF は tsshogi の `Record` に手を足して `exportKIF` で作る（`src/tree/kif.ts`）。候補手の 1 番目が本譜、2 番目以降が変化。評価値・ラベル・未検証はコメント（`*`）に書く。
    合流した局面は 1 回目だけ先を書き、2 回目は「合流」のコメントだけ。文字コードは UTF-8 なので拡張子は `.kifu`
  - 共有は `navigator.share({ files })`。iPhone/iPad は「押した直後」でないと断られるので、共有の前に await を挟まない（ファイルの中身は同期的に作る）。
    使えない端末（Android の Chrome は .json・.kifu のファイル共有に非対応、PC）はダウンロード。KIF は「KIFをコピー」でクリップボードにも渡せる
- 取り込み（`src/tree/backup.ts` の `parseTreeJson`）：他人のファイルも読むので、形・局面・手の行き先をすべて確かめる。同じ id があれば「上書き／別のツリーとして追加／やめる」を聞く
- 生成中のツリーは削除・上書きできない（自動保存で元に戻ってしまうため）。名前の変更は、開いているツリーそのものを書き換える
