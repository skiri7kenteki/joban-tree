# CLAUDE.md と関係する設定ファイルの整理（依頼と、決まったこと）（2026-11-28。段階の番号なし）

## 依頼の文（持ち主）

CLAUDE.md と関係する設定ファイルを、Opus 5.5 向けに整理してください。アプリのコードと動きは変えません。

### まず調べる（ファイルはまだ直さない）
1. `/doctor prompt-audit` を実行する。CLAUDE.md、.claude/rules/*.md、.claude/skills/ のスキル（start-stage・finish-stage など）、サブエージェント（test-runner など）が対象。
2. ~/.claude/CLAUDE.md があれば、それも見る。
3. そのうえで、下の「直したい所」が本当に当てはまるかを確かめる。

### 直したい所
1. 「これからの方針（段階17〜）」の節が古い。段階17〜22 はもう終わっているのに「予定」として書かれていて、経緯も残っている。
   → 今も通用する考え方（作る→覚える→実戦で確かめる、使う場面は将棋ウォーズ、手順を通して覚える、戦型は横歩取り中心、仲間との共有は考えない）だけを数行で残す。経緯は docs/claude/history.md へ移す。5行目の「前の対策ツリーを消した」という説明も同じように移す。
2. 同じことが2か所に書いてある（Google ドライブの例外・「テーマは1つだけ」→ 1か所に。commit → pull → push の流れ → CLAUDE.md には「push の前に必ず git pull --rebase」と「公開する変更のたびに version を上げる」だけを残し、手順は /finish-stage に任せる）。
3. 画面の作業でしか使わない情報が、毎回読み込まれている（色の細かい決まり → DESIGN.md か ui.md に無ければ移す。CLAUDE.md には「見た目は DESIGN.md のいちばん上の『画面の決まり』に従う」だけ／字体の細かい所 → folders.md／「全部を流す」テストコマンド → /finish-stage。途中で使う「関係するものだけ」は CLAUDE.md に残す）。
4. 太字が多い。破られると困る所だけを残す。
5. 進め方に 1 行足す：「段階の途中は、原因の分からない失敗が出たときや仕様にない大きな選択が出たとき以外は、止まらずに進める」。

### 変えないもの
- 「どの作業でも守ること」の中身
- 「機能ごとの仕様の場所」の表
- 段階ごとに止まって報告する、大きな選択は質問するという決まり
- 「やらないこと」の中身（まとめるのはよいが、項目は減らさない）
- 決まりそのもの。移す・まとめる・短くするだけにして、意味が変わる削り方はしない

### 進め方
- 最初は、調べた結果と直す案だけを出して止まる。了承したら直す。直したあとは、移した決まりが移し先にちゃんとあるかを 1 つずつ確かめる。
- version は上げない。テストは `npm run typecheck` と `npx vitest run tests/unit/rules.test.ts` だけ（test-runner に任せる）。
- PROGRESS.md に 1 行書いて commit し、git pull --rebase してから push する。

## 決まったこと（2026-11-28「おすすめの通りで」）
1. 全部を流すテストコマンドは、/finish-stage ではなく test-runner.md に書く（流す側はスキルの中身を受け取らないため）。
2. 「作業の区切りごとに commit し、PROGRESS.md を更新する」は 1 行残す。
3. 「止まらずに進める」の行に「（データを消す・上書きするなど、確認が要ることは今まで通り聞く）」を付ける。finish-stage の「途中で失敗したら止まる」は、原因が分からない失敗・回避策が要る失敗に合わせる。
4. ルールと DESIGN.md の古い記述は、確かさが「高」と「中」のものを今回直す。DESIGN.md の古い盤と駒の説明は history.md へ移し、今も使う値はコードと照らして残す。

別の作業にしたこと：`public/manifest.webmanifest` と `index.html` の `theme_color` が紺の `#1c2740` のまま（アプリの変更になる）。
